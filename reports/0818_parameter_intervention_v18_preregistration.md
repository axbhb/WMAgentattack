# Parameter intervention v18 preregistration

Date: 2026-08-18

Status: frozen before manifest construction and before any v18 outcome is executed.

v17 proved strong ordinary action-effect identifiability but failed because successful clean argument donors never crossed execution boundaries. v18 changes one mechanism only: hold root state and tool fixed, then compare a valid control argument payload against a schema-valid one-field mutation that violates a documented simulator precondition. No result from the new branch is used in selection.

There are 12 task pairs, one per suite × difficulty cell. Banking changes only the transaction ID, Slack only the user, Travel only the start date, and Workspace only the file ID. Each control and corruption is executed from a fresh reconstruction twice. The fixed budget is 24 rows, 48 branch executions, 76 prefix replay calls, and 124 synthetic sandbox tool calls. There are no LLM, attack, model-training, Dreamer, or real-endpoint calls.

The gate requires all 12 pairs, all 12 controls to succeed, at least 10 corrupted rows to error, at least 10 paired success→error flips, at least 10 effect changes, byte-identical replicas, exact replay, no leakage, and at least one status flip in every suite. Thresholds cannot change after execution.
